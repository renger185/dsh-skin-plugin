## v1.8.13 ｜ 2026-10-22

**主题：图库里的「换一张」改成「下一张」—— 按图库排列顺序走下一张。**

boss原话：「**把这里的『换一张』变成『下一张』，意思是按照当前的图片排列，变换成下一张的壁纸，因为下面已经有了『自定义随机换一张』**」

### 为什么原来那个按钮该改（不是换文案，是换行为）

原来「换一张」调的是 `pickRandomImageId()` —— **随机抽**（`Math.random`），
而**下面「背景图片随机变换时间」用的是同一个函数**。
⇒ 两个入口干同一件事，随机模式下还常出现"点了没变化"（抽到当前这张就要再抽一次）。

boss这句话等于点明：**随机那一套已经有地方了，这个按钮该走顺序**。

### 改成了什么

新增 `pickNextImageId()`：**按图库 `library` 数组的顺序**往后走一张，**到最后一张回到第一张**（循环，不越界）。

- 顺序依据 = 图库里缩略图**从左到右的排列**（`GalleryStrip` 就是 `library.slice(0, shown)` 渲染的），
  **boss看到的排列就是判据**，不是我另排的。
- 当前那张**不在图库里**（被删了/换过）→ 从第一张开始。
- 图库只有 1 张 → 按钮不显示（跟原来一致）。
- **自动轮换那一路仍然是随机的**（那才是它的本意），没动。

### 顺手修掉的一个坑（样张在骗人）

`verify/panel_real_visual.cjs` 的中文词典是**手抄**的 —— 改了代码之后它还在显示旧文案「换一张」，
**样张看起来像没改**。现在改成**从真代码里抠文案**，手抄的字典天生会漂，抠才不会。

### 验证

- `verify/full_feature_suite.cjs` 122 → **132 项全过**，新增 10 条盯这次的事：
  文案是「下一张」、有 `pickNextImageId`、**下标 +1 且末尾循环**、按钮调的是顺序那个**不是**随机那个、
  自动轮换仍然随机；并且**真跑一遍顺序逻辑**（a→b、c→a 循环、不在图库→第一张、只有一张→不换）。
- `verify/four_features.cjs` 23 → **24 项全过**（原来那条「点了会抽一张」也改成盯顺序）。
- 其余 10 套回归全过；版本对账三处一致；脱敏闸门 0 命中。

## v1.8.12 ｜ 2026-10-22

**主题：「检查更新」弹出的窗口底色太透，底下的字看不清 —— 压实。**

boss原话：「**检查更新跳出来的页面透明度太低了，你要提高点，否则我们在切换背景的情况下，因为透明度太低，导致前面显示的文字看不清楚了**」

### 根因（查实的，不是猜）

那个窗口原来直接用 `T.surface`（= `--dsw-alias-bg-overlay`），而这枚 token 的不透明度**被乘了 0.6**：

```js
{ name: '--dsw-alias-bg-overlay', lift: 0.04,
  floor: () => Math.max(PANEL_FLOOR, normalizePopupAlpha(state.popupAlpha) * 0.6) }
```

那个 `0.6` 是 **10-18 为「下拉菜单」调**的（当时boss说「毛玻璃透明度别那么低」），后来顺手把
`--dsw-alias-bg-overlay` 也加进了同一批。默认 `popupAlpha=0.95` → **实际只有 0.57**，
聊天区的字和壁纸就一起透上来了。

### 修法（只动这个窗口，不碰全局）

- 底色换成**近乎不透明的实色** `rgba(255, 255, 255, 0.97)`；
- 加毛玻璃模糊 `blur(24px) saturate(1.6)`，边缘看着还是通透的，不像贴了块白纸；
- 阴影加深一点（0.34 → 0.42），从背景图上"浮起来"。

⚠️ **为什么不改 `--dsw-alias-bg-overlay` 本身**：那一枚是全局的，
改了会把下拉菜单、弹窗、输入框一起变浓 —— 超出boss这次说的范围。

### 实测（不是"感觉变实了"）

新增 `verify/update_window_opacity_compare.cjs`：同一张图渲染三版（无窗口 / 改前 / 改后），
量**窗口那块地方像素的起伏**（起伏全部来自「底下的字透过来」）：

| | 起伏 | 残余比 |
|---|---|---|
| 底子原样（无窗口） | 49.47 | 100% |
| **改之前** | 21.45 | **43.4%** ✗ 透得太多 |
| **改之后** | 1.63 | **3.3%** ✓ 压得住 |

**底下的字从 43.4% 压到 3.3%（压掉 13 倍）。**

### 过程中踩的三个坑（都关于"CSS 到底生效没有"）

1. **多层 `background` 简写会被浏览器整条作废**。第一版想"半透主题色 + 近乎不透明的白底"两层，
   写成 `background: [A, B].join(',')` —— **Chromium 里层类型/数量不匹配会整条解析失败**，
   结果连半透那层都没了，中心像素还是底下的深色（65,70,78），**看起来跟没改一样**。
   ⇒ 改成**单层实色 + backdrop-filter**，老老实实的。
2. **层序反了也等于白改**。CSS 多层 background 是「第一层在最上面」——
   半透那层写前面、实底写后面，实底被压在最下面透不出来。
3. **测量区选错，结论会反**。第一版量「窗口内容区」→ 量到的是**窗口自己的黑字**，
   得出"改后反而更差"的荒谬结论。正确做法是**窗口里不放任何文字**，量那块地方的起伏，
   起伏全部来自底下透过来的字。
   （还踩了一次：PowerShell 逐像素全扫 30 万次跑了几分钟卡住 → 改成每 4 像素取样。）

### 验证

`verify/full_feature_suite.cjs` 119 → **122 项全过**，新增 3 条盯这次的事：
底色**必须是单层**、**不透明度 ≥ 0.95**、**必须有毛玻璃模糊**。
其余 11 套回归全过；版本对账三处一致；脱敏闸门 0 命中。

## v1.8.11 ｜ 2026-10-22

**主题：悬浮窗面板的界面美化（只改样子，不动功能）。**

boss原话：「**对悬浮窗展开的选项做一个相关的界面美化，并且自检通过。要求不伤现在的核心功能。**」

### 做法：加一层**共用样式**，不改任何控件的逻辑

之前每一段都是**手写内联样式**，同样的东西抄了七八遍（`marginBottom: 18`、`fontSize: 12`、按钮圆角…），
结果是「改一处要改八处」，很容易漏、也很容易改串。
现在收进 `PANEL_UI` 一组常量 —— **面板整体长什么样，只由这一处决定**。

### boss能看出来的四处变化

| # | 改前 | 改后 |
|---|---|---|
| ① | 段标题是一行灰字，容易滑过去 | 标题前加**短竖条 + 加粗字**（跟面板大标题同一套） |
| ② | 一长条黏在一起，看不出分了几段 | 段与段之间加**分隔线**，成为一个一个的组 |
| ③ | 分段控件是四个描边按钮并排 | 改成**带底槽的胶囊**，选中项浮起来（白底+细边框+深字） |
| ④ | 说明小字挤在一起 | 小字**行高放宽**到 1.6，滑杆和数值也统一了字号字重 |

面板本身：内边距 14→16、圆角 14→16、加一层轻投影（从背景图上"浮起来"而不是贴着一块白板）。

### 「不伤功能」是怎么保证的

- **代码层面**：只加样式常量 + 两个渲染助手（`panelTitle` / `panelHint`），
  **所有 `onClick`、状态、存盘逻辑一个字没改**（分段控件 `segment` 的 onClick / disabled / aria-pressed 全部保留）。
- **验证层面**：**16 套自检全过**（含自动更新的 27 项、贴纸 125+26+33、手势 31、全功能 119…），
  并新增 18 条判据**专门盯核心功能还在不在**（恢复默认/检查更新/三个模式/明度滑杆/换一张/自动换肤档位/竖图五档/提示音开关与试听/音量/语言切换/图库/拖动/关面板）。
- **看图验证**：新增 `verify/panel_real_visual.cjs` —— **直接把生产代码里的组件跑起来**渲染成 png，
  不是手写一份 HTML 冒充（手写样张 = 凭想象画，本项目已经吃过这个亏）。

### 过程中踩的坑（都在验证脚本里，与插件无关）

抠组件源码时：**`SkinControls({ compact })` 的第一个花括号是参数解构、不是函数体** ——
从那儿开始配平只会切出 47 个字符，于是 `new Function` 报「Unexpected token 'return'」。
修法：先配平圆括号跳过参数列表，再配平大括号取函数体。
另外缺外部变量时，改成**跑一次、按 ReferenceError 自动补一个、循环到不报错**（上限 60 次），
不用一个个试（本轮补了 6 个）。

## v1.8.10 ｜ 2026-10-22

**主题：修界面文案里的 Markdown 星号（boss重启后一眼看见的）。**

boss 10-22 14:0x 重启后，界面上更新提示那几行**显示着两个星号**。

- **根因**：写文案时顺手打了 `**加粗**`（Markdown 记号），但**这个插件不渲染 Markdown** → 界面上原样显示 `**`。
- **修法**：4 条文案（中英各 2 条）去掉 `**`。
- **防退化**：新增判据「界面文案里没有 Markdown 星号」——
  ⚠️ 查法踩了两次坑：① 「从 const DICTS 往后 14 万字符再找带 `**` 的引号串」会把**注释和代码**一起扫进来；
  ② 「只认整行是纯字面量」又抓不到，因为真代码是 `key: '...',` 这种。
  正确做法：**先剔注释，再找字符串字面量里的 `**`**，并做了一次变异检验（塞一行带星号的进去，判据确实报红）。

## v1.8.9 ｜ 2026-10-22

**主题：自动更新做成「下载到旁边 → 您点一下确认才替换」。**

boss原话：「做成**『下载好放在旁边，由您点一下确认才替换』**——既省事，又不越界。」

### 三步，界限清楚

| 步骤 | 界面上的按钮 | 做了什么 | 会不会动用户文件 |
|---|---|---|---|
| ① | 「检查更新」 | 只问远端版本号 | ❌ 不会 |
| ② | 「**下载更新（不替换）**」 | 下载到**暂存目录**，逐文件核对 SHA-256 | ❌ **一个字节都不碰现装的那份** |
| ③ | 「**点此安装（替换现有文件）**」 | 先备份 → 写新文件 → 核对 → 失败自动回滚 | ✅ 只有用户点了才动 |

界面文案明说「下载（不替换）」「点此安装才替换」，并提示**替换后需要重启桌面端才生效**（页面代码是启动加载的，重启由用户自己来）。

### 两条安全底座

1. **下载阶段绝不碰现装的那一份。**
   下载失败 / 断网 / 哈希对不上 / 清单路径越界 → 全部**在暂存目录里被挡下**，现装的那份**毫发无损**，用户还在用。
2. **替换只在用户点了之后才做，且替换前一定备份。**
   顺序：备份 → 写新文件（先写 `.new` 再改名，避免写到一半把原文件截断）→ 核对哈希。
   **任何一步失败 → 从备份还原**，界面上明说"已回滚"。

### 关于签名（boss拍板「只要哈希，不要签名」）

清单里**只有 SHA-256，没有数字签名**。它挡的是"下载损坏/被截断"，
**挡不住"仓库被人改了"**（那需要 Ed25519 签发私钥 —— 另一件事，注释里写清了这条边界，不假装有签名能力）。

### 发布清单

新增 `publish/release-manifest.json`（由 `verify/make_release_manifest.cjs` 生成）：
逐个文件记路径 + 字节数 + SHA-256，**跟发布包里的文件一一对应**（脚本会反查"发布包里有没有漏进清单的文件"）。
别人装的插件从这个地址读：`cdn.jsdelivr.net/gh/<owner>/<repo>@<branch>/publish/release-manifest.json`。

### 验证

`verify/update_apply_check.cjs`（**新增 27 项**，全过）——这功能会**动用户机器上的文件**，所以判据覆盖最要命的几件：

| 场景 | 判据 |
|---|---|
| 下载阶段 | 现装那份**内容没变**；新文件落在暂存目录（不污染安装目录） |
| 哈希对不上 | 回 `hash-mismatch`，现装那份不受影响 |
| 清单塞了 `../` 越界路径 | 回 `manifest-path-invalid`，逃逸文件没被创建 |
| 没点确认 | 现装那份**仍然是老的** |
| 点了确认 | 替换成功 + **旧版确实被备份下来了** + 提示需要重启 |
| 替换中途失败 | 回 `replace-failed` + **标了"已回滚"** + 已写的文件**还原回替换前的样子** + 不留半成品 |
| 没下载过就想替换 | 回 `nothing-staged`（不许凭空装） |

### 过程中抓到的 4 个真 bug（都是自测抓出来的，不是猜的）

1. **主机端没 `import crypto`** —— 用了 `crypto.createHash` 但没导入 → 下载直接抛 `crypto.createHash is not a function`。**这个 bug 在真机上会 100% 触发**（下载必失败），静态检查完全看不出来。
2. **暂存状态里存了文件数而不是文件清单** —— 替换时要遍历文件 → `for (const file of 数字)` 抛 "number is not iterable"，而且报的是 `backup-failed`，**跟真正的原因对不上**，极难查。
3. **路径拼错一层** —— 清单路径是仓库结构（`plugin/index.js`），而**安装目录本身就是那个 `plugin/`** → 直接拼会变成 `plugin/plugin/index.js`，写到一个不存在的地方（界面显示"替换成功"，实际什么也没换）。已加 `toInstallRelative()` 换算。
4. **一个坏条目让整次备份失败** —— 单个文件备不下来（目标是目录）就整体 return，**把整次更新挡掉**。改成"跳过它、记下来、继续备其他的"，坏文件留到替换阶段才报 + 回滚。

### ⚠️ 现在还用不了（前提没满足）

**远端 GitHub 仍是 1.6.0**（boss 10-22 09:0x 拍板「先不推，只把功能写好」）。
所以：**别人（和本机）点「下载更新」会下到 1.6.0**（比本地 1.8.9 旧）。
**要把这个功能真正跑起来，得先把 1.8.9 推到 GitHub**（含 `publish/release-manifest.json`）。

## v1.8.8 ｜ 2026-10-22

**主题：悬浮窗上多一个「检查更新」按钮，点开一个独立新窗口（更新 + 我的项目）。**

boss原话：「**在换肤悬浮窗上，左边是默认界面，右边是『检查更新』。点击『检查更新』之后，不要直接更新，而是弹出一个新的画面窗口。新窗口的底色按照现在的悬浮窗模式来。形式可以借助我们现有安装的这个插件 Our Free Model，我们直接检查里面的两个：一个是插件升级，一个推荐项目，推荐项目就写我们自己的项目，目前只有一个手机远程。**」

### 布局：一页两段，不拆 tab（问过boss，选了「一页两段」）

Our Free Model 那边是**拆成两个 tab** 的（`插件升级` / `推荐项目`），但换肤这边**不照搬**：

| 为什么不拆 tab | 依据 |
|---|---|
| 换肤面板只有 460px 宽，加一层 tab 导航更挤 | `PANEL_WIDTH = 460`（代码常量） |
| 「看自己的项目」比「查更新」常用得多，拆开要多点一次 | 两件事使用频率差一个量级 |
| 拆开会割裂——它们本来就是同一套东西 | 都是boss自己写的、给别人用的插件 |

但**两段必须视觉上分得清楚**：中间一条分隔线 + 各自小标题（「插件升级」／「我的项目」），不能糊成一坨。

### 新窗口是什么样

- **独立浮层**（不是浏览器新标签页），居中，`position: fixed`。
- **底色跟着现在的换肤模式走**（用 `T.surface` 那一套 token —— 专注/休闲/正常各自不同）。
- 关闭方式三个：右上角「×」、按 **Esc**、**点窗口外面**（跟面板一致，别让boss猜）。
- **点「检查更新」只查版本，不会自动替换任何东西**；想更新得点「去仓库页」，自己下载覆盖、重启桌面端生效。
  （不在插件里偷偷下载替换 —— 装不装由人决定。）

### 「我的项目」那段的纪律（照抄 Our Free Model 的做法）

**数字必须是真读回来的**：Star / Fork / 最近提交由主机端实时打 GitHub API，
**读不到就不显示那个数字**，绝不用占位数字凑版面 —— 这一段的说服力全在"数字是真的"。

目前只列**手机远程**（`renger185/dsh-phone-remote`，公开、`main`）。项目清单走配置（`updateProjects`），不写死在代码里。

### 顺带修掉的一个真 bug

**`pushed_at` 是字符串不是时间戳**：第一版直接 `Number(data.pushed_at)` → 恒为 `NaN` → 0 → 「最近提交」那一栏**永远空白，而且不报错**（极难发现）。
改成先 `Date.parse` 再取时间戳。

另外：两个仓库的清单**不在同一个位置** —— 换肤的在 `plugin/package.json`，手机远程的在**仓库根目录**。
写死路径查手机远程会一直 404（已实测），所以路径也走配置（`updatePkgPath`）。

### 验证

- `verify/full_feature_suite.cjs` 84 → **100 项全过**，新增 21 项（新窗口形态/两段分隔/三个关闭方式/不自动下载/数字纪律/`toMs` 转换/配置化项目清单…）。
- **真机实测两个接口**：update-check **722ms** 返回真实远端版本；projects **558ms** 返回手机远程 `Star=1 / Fork=0 / 最近更新 21 小时前`（真值）。
- 新增 `verify/update_window_visual.cjs` 出样张（数据真读、样式从源码抠）。
- 其余 10 套回归全过；版本对账三处一致；脱敏闸门 0 命中。

## v1.8.7 ｜ 2026-10-22

**主题：插件自己查新版本，面板里提示「有新版本 vX」。**

boss问：「**别人下载了 GitHub 上的插件，我们更新之后，他会收到升级的通知吗**」→ 查完的答案是**不会**：

| 查了什么 | 结果 |
|---|---|
| 插件自身有更新检查吗 | **没有**（搜 `checkUpdate / latestVersion / 新版本` 零命中） |
| GitHub 会通知下载过的人吗 | **不会**，只通知 watch 了 Release / 订阅仓库的人，与"下载过"无关 |
| DSH 有插件更新徽标吗 | **有**（「有新版本 / 可更新」），但它只认**它自己的插件市场目录** |
| 我们在那个目录里吗 | **不在**（目录里那条 `dsh-skin-market 0.1.63` 是**别人的另一个插件**，名字像而已） |

boss选了 B：**插件自己查**。于是这一版：主机端去问远端仓库的版本，面板最上面出一行「有新版本 vX」，点一下打开仓库页。

### 怎么查的（两个源，谁通用谁）

| 顺序 | 源 | 备注 |
|---|---|---|
| ① | jsDelivr CDN `cdn.jsdelivr.net/gh/<repo>@<branch>/plugin/package.json` | 国内通常可达 |
| ② | GitHub contents API（base64 解回 JSON） | 兜底 |

⚠️ **`raw.githubusercontent.com` 在部分网络下不通（本机实测就不通）**，所以不能拿它当唯一来源 —— 这是本轮实测结论，不是猜的。

### 纪律

- **只有确实有新版本才显示**：没配置 / 没网 / 两个源都失败 / 版本不比本地新 → **面板一个像素都不变**。更新提示是加分项，不能因为没网就挂红字吓人。
- **6 小时内只问一次**（主机端缓存；页面也缓一层）：未认证的 GitHub 接口 60 次/小时就限流。
- **点提示只打开仓库页**，不在插件里偷偷下载替换（装不装由人决定）。
- 要真通知到别人，**前提还是得把新版推到 GitHub**（远端现在是 1.6.0，本机 1.8.7）。

### 验证

- `verify/full_feature_suite.cjs` 61 → **84 项全过**，新增 7b 共 23 项：
  - 版本比较真跑：`1.9.0>1.8.6`、`1.8.7>1.8.6`、同版本不算新、远端更旧不算新、`1.10.0>1.9.9`（段数不同不误判）、带 `v` 前缀与 `-rc.1` 后缀、空值不炸
  - 接口真跑（假远端）：有新版本 / 同版本 / 两个源都失败不崩 / 失败时两个源都试过 / 没配置回 `not-configured`
  - 页面侧 7 条：只有 `outdated` 才显示、点开仓库页、中英文案、6 小时缓存
- **真机实测**（不是假绿）：打真实接口 **722ms** 返回 `{current:"1.8.7", latest:"1.6.0", outdated:false, source:"jsdelivr"}` —— 远端还没推新版，所以正确地**不提示**。

### 踩的坑

**把全局 `fetch` 换成假远端去做测试，连"我自己打本机接口"那次请求也被假掉了** —— 判据拿到的是假远端的 JSON，红得莫名其妙。
修法：打接口用真 `fetch`（另存一份），只有插件内部访问远端才走假 `fetch`。

### 抓到并修掉的 2 个真 bug

**① 恢复默认时落盘漏了 `lastWallId`**
- 现象：点「恢复默认界面」→ 重启桌面端 → 双击右键，切回去的**不是恢复前那张**（是图库第一张或更早的）。
- 根因：`restoreDefaults()` 内存里保留了这张图，但 `saveState({...})` 没把它发给主机端 → 存档里还是旧值。
- 修法：落盘时带上 `lastWallId: keepWallId`。

**② 窗口变窄后悬浮球跑到屏幕外**
- 现象：宽屏把球拖到右边 → 把窗口拖窄 → **球看不见了**（只能把窗口再拉宽找回来）。
- 根因：夹紧只在**启动时**做一次，运行中窗口变化没人管。
- 修法：抽出纯函数 `clampBallXY(x, y, 视口宽, 视口高)`，启动读档和窗口 resize 都用它（一处口径，不各写一套）。

两个 bug 都写了**防退化判据**（真跑夹紧函数：负值/NaN/超界/窗口比球还窄；静态查恢复默认的落盘里有没有 `lastWallId`）。

### 顺手记一笔：有一个自检脚本自己会挂住

`verify/frosted_check.cjs`（竖图分层那套）**跑完不退出**——它跑完 mock 渲染后没 `process.exit`，

（本轮先用超时跳过，没改它；要改成"跑完即退"随时可以做。）

### 一个要boss定的交互冲突（本轮没擅自动）

**切回默认壁纸之后，如果「自动换肤」还开着，到点它会把壁纸又换回来** —— 双击右键的效果等于被抹掉。

- A. 切到默认时**自动暂停**自动换肤（手势意图最直白：我要干净的界面）
- B. 不动它（自动换肤开着就是"我自己会换"，切成默认只是临时的）

## v1.8.4 ｜ 2026-10-22

**主题：双击右键「切回上次那张」改成落盘 —— 重启后也记着。**

boss确认：「**对的 我们就是在插件里面的壁纸做自定义快捷切换**」

### 为什么要紧跟着改这一版

v1.8.3 里「上次那张」只记在内存里，**重启桌面端就丢** → 双击右键切回去的是**图库第一张**。
那就不叫"自定义快捷切换"了（切回去的可能根本不是你刚才那张）。既然boss明确是插件内壁纸的快捷切换，
"记住哪张"就必须跟其它设置一样**存盘、跨重启**。

### 改了什么

| 地方 | 改动 |
|---|---|
| `plugin/index.js` | `emptyState()` 加 `lastWallId: ''`；落盘归一化里加一行（只认字符串，老存档没有这个键就是空串，不猜） |
| `plugin/client.js` | 切默认时把当前那张写进 `state.lastWallId` 并一起落盘；切回时读它；`normalizeState()` 的返回值**补上这个字段**；`restoreDefaults()` 也留着它（撤了壁纸之后仍能双击右键切回来） |

### 抓到一个必然会犯的坑（本轮最有价值的一条）

**`normalizeState()` 会整个换掉 state 对象**——它是"白名单式重建"，返回值里漏哪个字段，那个字段就在每次规范化时被抹掉。
第一版就漏了 `lastWallId`，症状会非常迷惑：**「切回上次那张」有时灵、有时不灵**（取决于这次会话中途有没有走过一次规范化）。
判据现在直接盯三处：默认值里有、`normalizeState` 返回值里有、主机端归一化里有。

### 验证

`verify/ball_gesture_check.cjs` 22 → **26 项**，新增的关键一条是**跨重启模拟**：
换一个全新实例、只把存档里的 `lastWallId` 带进去 → 必须切回 `img-A`（若退成图库第一张 `img-B` 就算没落盘）。
另外三条盯"三处都得有这个字段"。

## v1.8.3 ｜ 2026-10-22

**主题：悬浮球加「双击右键」—— 自定义背景 ⇄ 系统默认壁纸。**

boss原话：「**双击右键切换为自定义背景，或者是双击右键从自定义背景切换成系统的默认壁纸**」

### 以前是什么样（先说清，免得以为是坏了）

**插件里一条右键处理都没有**（全文件搜 `onContextMenu` 零命中）。所以：

| boss以为的 | 实际 |
|---|---|
| 右键两下切换壁纸 | ❌ 右键什么都不做，只会弹系统默认菜单 |
| 切到系统默认壁纸 | ❌ 没这个能力（面板里只有「恢复默认界面」，会把配色/模式一起撤） |

| 当前状态 | 双击右键之后 |
|---|---|
| 挂着自定义壁纸 | 撤掉壁纸，回到没装换肤时的样子 |
| 没有壁纸（默认） | 换回**上一次那张**自定义壁纸（记住的那张被删了，就退图库第一张） |

- **单击右键不动作**（boss要的是双击；两下超过 260ms 也当两次单击，不动作）。
- **只撤壁纸**，不碰模式、文字颜色、自动换肤开关 —— 那是面板「恢复默认界面」的活，不是这个手势的活。
- 右键计数跟左键**各算各的**，互不干扰；刚拖过球不会误触发。
- 切完给一句提示条（中英双语）：`已切回系统默认壁纸` / `已切回自定义背景` / 图库空时 `图库是空的,先加一张图`。

| 脚本 | 项数 | 查什么 |

## v1.8.2 ｜ 2026-10-21

**主题：贴纸加第二张表——「不可用」（今天真报过错 / 真用不了的模型）。**

boss原话：「**你再帮我查一下『贴纸』里对当前本地模型的识别，我感觉没那么准确。因为有些模型已经报 429 错误或者接口不可用了，但『贴纸』里并没有记录。如果不是解禁的话，你就再起一个表头，写上『不可用』或者『禁用』，这样我就能理解了。**」

### 原来为什么"报了 429 却没记录"

贴纸原来只认**一种**状态：`modelRateLimits` 里**有解禁时刻**的限流。剩下全漏了：

| 真实情况 | 以前 | 现在 |
|---|---|---|
| 撞额度型 429、拿到解禁时刻 | ✅ 显示（表一） | ✅ 表一 |
| 今天请求**全部失败**（接口挂/鉴权错/连不上） | ❌ 不显示 | ✅ 表二「全失败 2/2」 |
| 今天失败率过半（偶发不算） | ❌ | ✅ 表二「失败 3/5」 |
| 渠道账号被停用 / 凭据过期（今天确实发过请求） | ❌ | ✅ 表二「渠道停用」「凭据过期」 |
| 模型已被实证下架（dead-models.json） | ❌ | ✅ 表二「接口不可用」 |
| 只是被禁用、今天一次没调过 | ❌ | ❌ **仍然不写**（boss划的边界） |

### 数据从哪来（新增读取，全部只读）

`~/.dsh/channel-pack/` 由 DSH 的 Channel Pack 插件自己维护，贴纸**只读不写**：

| 文件 | 拿来干什么 |
|---|---|
| `state.json` | `accounts[].enabled` / `expiresAt`（停用、凭据过期）、`disabledModels`（黑名单） |
| `token-ledger.json` | `days[今天][<渠道|账号|模型>]` 的 `requests` / `errors` —— **判"今天真失败过"的唯一依据** |
| `dead-models.json` | 已被实证「模型不存在」的模型（可缺，缺了就不判这条） |

路径不写死：配置 `channelPackDir` 可覆盖，不配就按 `$DSH_HOME`（默认 `~/.dsh`）推 `channel-pack`；读不到就这一栏空着，**不影响表一**。

### 判据（写进代码注释，也写进自检）

一条记录要进表二，**至少命中一条实证**：
1. 今天 `errors = requests`（全失败）
2. 今天失败率 ≥ 50% 且请求 ≥ 2 次（偶发 1 次错误不算"不可用"，否则满屏假红）
3. 账号停用 / 凭据过期（且今天确实有请求）
4. 在 `dead-models` 里（接口不可用）

另外：**还在限流的（表一已写）不会在表二重复**；只有**报过错之后**被禁用的才追加「已禁用」——光在黑名单、今天没调过的一律不写。

### 表二长什么样

第三列表头写「**不可用**」，格子里给原因（`全失败 2/2` / `失败 3/5` / `渠道停用` / `凭据过期` / `接口不可用` / `… · 已禁用`）。
- **红点** = 报错了还没恢复；**灰点** = 已经被禁用。
- 超过 10 条折叠，点「展开（还有 N 条）」，跟表一同一套交互。

3. **球的宽高漏了 → 摆位算成 NaN**：真机上 `width/height` 来自 `getBoundingClientRect`，样张里只给了 left/top/right/bottom，结果 `cx = left + width/2` 变 NaN，top 直接 NaN 还在出图（没抛错）。已补上，并加了"样张自己必须在屏幕内，否则退出码 1"的闸门。

### 验证踩的坑（都是「测试自己骗自己」那类）

1. **清理函数不能马上调**：迷你 React 里 `useEffect` 先调 `fn()` 再立刻调 `cleanup()` → 拉数据那个 effect 的 `alive` 被置 false → Promise 回来后数据被丢弃 → **行永远渲染不出来**，判据红得莫名其妙。改成「清理函数只存不跑」。
2. **假接口形状要跟真的一致**：`getJson` 真身返回**已解析的 JSON**，第一版假接口返回的是 Response 壳 → `data.items` 恒为 undefined → 每次拉数据都 `new []` → `setItems` 认为变了 → **无限重画，把 node 撑到 4GB 崩掉**。修法：假接口直接返回 `{ items }`，并给迷你 React 加「重渲染超过 200 次直接报跑飞」的硬闸门。
3. **样本喂错会得出错的结论**：验「至少三处 700 加粗」时没喂行数据 → 「模型名」那列根本不存在 → 只数到 2 处，看着像字重没改。**先确认样本能让判据看得见**，再信判据。

## v1.8.0 ｜ 2026-10-20

**主题：修「完成任务提示音」真正的主因——多会话并行时永远不响。**

作者原话：「**为什么完成任务有的时候有声音，有的时候没声音了**」（23:4x 第二次报同一个问题）

### 为什么这次才找到真凶

20:1x 那版（B 方案）补了三个漏响的洞，但**主因没动**。这次加了**留痕**（bell 接口回 `trace`，最近 10 次判定原因），一眼就看见现场：

```
23:49:48  还有 5 个在跑，先别响
23:50:09  还有 5 个在跑，先别响
23:50:41  还有 5 个在跑，先别响
23:50:54  还有 5 个在跑，先别响
23:51:07  还有 4 个在跑，先别响
23:51:18  还有 4 个在跑，先别响
23:51:32  还有 3 个在跑，先别响
23:53:29  还有 5 个在跑，先别响
```

**N 的序列 5→5→5→5→4→4→3→5：有进有出（账本是活的，不是卡死），但从来没到过 0。**

### 根因

旧判据是「**所有** agent 都空闲」才算完成。而这台机器上 **10 个会话目录**，boss多会话并行干活 —— **只要别的会话还有一个在跑，这一轮就永远判不完成，一声不响**。

**这不是"偶尔"，是"多会话并行时基本不响"。**

### 修法：按支记账

把「一个全局本子」改成「**每个根会话一个本子**」：

| | 旧 | 新 |
|---|---|---|
| 记账范围 | 所有 agent 混一本子 | **按根会话分开记**（子 agent 归到它的主会话底下） |
| 完成判据 | **所有**会话都空 | **这一支**空（自己 + 它的子 agent） |
| 谁的完成会响 | 全员空闲时 | **根会话**跑完就响（子 agent 干完不算） |

**为什么不能"谁跑完谁就响"**：那正是 10-19 20:4x 修掉的毛病（子 agent 先干完就响，主任务还在跑）。现在保留那道防线，只是把"所有会话"收窄成"这一支"。

**怎么找根会话**：`payload.agent` 是活的 Agent 对象，带 `.session`；子 agent 的 session 有 `header.parentSession`（指向主会话），主会话没有 ⇒ 它自己就是根。⚠️ 读不到父子关系时退化成「按自己算一个根」——**宁可多响一声，也不能因此永远不响**。

### 验证

`bell_signal_check.cjs` 新增三个场景（31 → 40 项）：
- **1b 多会话并行**：A/B/C 三个会话同时在跑，A 干完就响（不再等全员空）
- **1c 子 agent**：子 agent 干完不响，主会话干完才响
- **1d 补响**：这一支被拽走后补响，别的会话在跑也不影响

`bell_signal_check` / `bell_check` / `full_verify` / `sound_check` / `sound_quota_check` / `panel_order_check` 全绿。

### 顺带

`sound_check.cjs` 的「维护阶段假空闲被排除」那条判据**是错的**（20:1x 已证实那个判断是空转、删掉了，注释里还留着字样）→ 改成「只搜代码行、注释行剔掉再匹配」，并新增「留痕字段在不在」一条。

**主题：加了一张贴纸。**

贴纸本身是一块半透明毛玻璃板（`backdrop-filter: blur(22px) saturate(1.7)`），
上面列的是各条线路当前的限流情况：哪个渠道、哪个模型、几点解禁。

**设计上的几个决定**：

| 决定 | 为什么 |
|---|---|
| 「还在限流 / 已到期」由**主机端**判，页面只画 | 两边各算一套必然对不上。判据是解禁时刻，不是文件里有没有那条 |

| 读不到 / 台账坏了 → 返回空清单 | 贴纸是加分项，读不到就该是空的，不能把插件带崩 |
| 贴纸位置用**视口坐标**算，不跟着球走 | 球是 `position: fixed`；贴纸若用负偏移跟着它，窄屏时整张会滑出屏幕外 |

| 连击 | 干什么 |
|---|---|
| 1 下 | 开面板 |
| 2 下 | 自动换肤开关 |
| 3 下 | 贴纸浮现 / 收起 |

用**同一个计数器**分清三档：单击先挂 260ms 计时器，到点没等到下一下才算单击；
第二下到达时作废第一下的计时器并重挂，这期间来了第三下就是三击。

**代价（明说）**：双击比原来**晚 260ms** 才生效（原来第二下立刻触发）。
这是「加第三档」必然带的代价——不推迟就没法区分双击和三击。

## v1.6.1 ｜ 2026-10-20

**主题：修「完成任务有时有声音、有时没声音」。四处改动 + 一条留痕。**

作者原话：「**关于我们皮肤插件的优化，为什么完成任务有的时候有声音，有的时候没声音了？这是什么情况**」

### 排查结论（20:0x，全部实测，不猜）

先把 C 方案（换更可靠的信号源）验掉了：把桌面端程序里"允许转发给网页那一侧的信号"清单整个抠出来，一共 28 个，**里面没有 `turn/end`、没有 `session/event`、也没有 `agent/status`**。所以网页侧能拿到的官方信号里，没有任何一个能代表"任务真的跑完了" → **C 走不通，退回 B**（B = 补漏 + 声音不丢）。

### ① 记账本加清理（治"突然彻底没声了"）

原来只有 `agent/status` 一条路往记账本里加名字、摘名字，**没有任何清理**。万一某个后台小任务的"空闲"广播没被收到（广播早于插件挂上、或监听中途掉了），这个名字就永远留在本子上 → 之后每次判断都发现"本子不空"→ **从此一次都不响**。

现在 `agent/disposed`（任务被收掉）时把名字划掉，划完**再评估一次**：万一是它卡住才不响的，这一步就补回来了。

### ② 取消后必须补响（治"任务明明完了没声音"，最常见）

原来"全部空闲"→ 安静等 3 秒，这期间任一路又跑起来就 `cancelSettle()` 作废、**不补** → 这台机器上有定时任务/后台自动化，任务真干完的那一刻只要被别的事拽走，这一次完成就被吞掉。

现在拽走时记 `pendingRefire`，等这波真安静下来**补一声**。宁可多响一声，不再吞。

### ③ 删掉两道多余的门槛

- **`sawRunning`**（"见过 running 才算完成"）：造成"插件挂上之前就已经在跑的任务，跑完了不响"。它想防的情况（主机留着旧时间戳一启动就补响）页面侧 10-19 19:5x 已经用 `bellSeenOnce` 解决了 —— **两道门槛防同一件事，留着的这道只会牺牲**。
- **`phase.kind === 'maintenance'` 判断**：去桌面端核实过，这个广播 `emit("agent/status", { status })` **只带一个字段**，`payload.phase` 永远是 undefined → 那道 if 从来没有拦住过任何东西。**被常量/字段锁死的条件不是"没触发"而是"不可能触发"，拿它当安全证明＝假绿**（跟 16:2x 蓝字那次同族）。

### ④ 加留痕：读一次就知道刚才为什么响/不响

bell 接口多回一个 `trace` 字段（最近 10 条判定原因，人话）。boss报"刚才没声音"时不用再靠猜。

### 第一版为什么收不到（技术原因记清楚）

| 事件 | 怎么发的 | 插件能不能收到 |
|---|---|---|
| `agent/status`（完成用） | `agentEvents` 里的 `ctx.events.dispatch(...)` —— **全局广播** | ✓ 能（所以「完成」一直好使） |
| `approval/asked`、`user-questions/request` | 按**会话 / 智能体作用域**发（`ctx.waterfall(scopeTarget(agent, agent), ...)`、`session/event`） | ✗ 收不到：插件挂在旁边那一支，**不在那条链上** |

**教训：同样是「事件」，一个有全局分发、一个按作用域冒泡 —— 不能因为前者能收就假定后者也能收。**（这是今天第五次同类：拿 A 的机制套 B。）

### 第二版：改走应用自己那条页面通道

应用自己的「提问卡片」「审批面板」两个客户端插件，是这样接的：

```js
ctx.remote.$on('user-questions/request', (request, next) => ...)
ctx.remote.$on('approval/request',        (request, next) => ...)
```

`$on` 底下是 `events.subscribe(...)`（**订阅，不是替换**），所以我们的监听不会顶掉应用的回答逻辑。
照抄这条路，规矩不变：**响一声 → 原样 `next()`**，宁可少响一声，也绝不把卡片吞掉。

- `watchHumanInteractions(remote)`：注册两个事件、只听不改；拿不到 `remote` 就安静返回 0（**不写进 `inject`** —— 万一它不是可注入服务，写了会让整个插件起不来）。
- 响的时候**直接用页面自己的播放**（不走主机 bell），所以「开关关着不响」也照旧。
- 主机端那两个监听**保留**（留着，哪天应用改成全局分发就自动生效），但注释里写明「真机上收不到，真正管用的是页面这条」。

## v1.3.4 ｜ 2026-10-19

**主题：提示音「提前响」—— 任务没完就响，一两分钟后才真结束。**

boss原话：「为什么有的时候任务还没跑完，但是它就已经声音提醒你了。但是基本上过一两分钟任务才结束。这种情况不多见」

### 查出两个原因（都会造成"提前响"）

**① 空闲 ≠ 干完了。** 应用里 agent 的状态是这么算的：

```js
get status() { return this.phase.kind === 'idle' || this.phase.kind === 'maintenance' ? 'idle' : 'running' }
```

**维护阶段（maintenance）也报成 idle** —— 而"压缩上下文 / 溢出恢复"这类维护正是**一轮任务干到一半**时跑的。于是 `running → idle(维护)` 骗着我们响了一声，等真干完（1~2 分钟后）又响一声。应用自己的文档甚至写着「Wait on durable events such as `turn/end` … **Do not poll `agent/status`**」。

**② 广播是所有 agent 的。** 子 agent、别的会话干完了也报 idle → 我们响了，可boss等的那件事还在跑。

### 现在的三道防线

| 防线 | 做法 |
|---|---|
| a. 排除维护中的假空闲 | `payload.phase?.kind === 'maintenance'` 就当没空闲（拿不到这字段也不怕，还有 b/c） |
| b. **按 agent 记账** | 谁在跑就往集合里加谁，谁空闲就摘掉；**只有所有 agent 都不在跑**才算一次完成（子 agent 先完不响、主任务完才响） |
| c. **静一静再响** | 全部空闲后再等 `bellSettleMs`（默认 3 秒），这期间任何一个又跑起来就取消（短促抖动不响） |

（`bellSettleMs` 可经插件 config 覆盖，纯粹为了测试能跑得快；默认 3000。）

### 验证

**新增 `verify/bell_signal_check.cjs`（功能测试）**：把主机端真正注册的那个监听函数**抓出来真跑**，按真机顺序喂事件，12 项全过：

- 任务干到一半跑维护 → **不响**；真干完才响；同一件事只响一次；
- 主任务 + 子 agent：子 agent 先完**不响**，两个都空闲了才响；
- 空闲一下又跑起来（抖动）→ 被取消不响，真安静下来才响；
- 刚启动就来的空闲（没见过 running）→ 不算完成。

`sound_check.cjs` 第 ③b 节加 6 项守着这三道防线。全套 **14 个脚本**退出码全 0；版本对账三处全对。

### 教训

**「状态变空闲」和「这件事干完了」是两件事** —— 借一个粗略的状态位去推一个精确的业务结论，边界上必翻车。（今天第四次同类：被常量锁死的条件 ≠ 没触发 / 值 0 ≠ 没见过 / 防呆 ≠ 用户要的区间 / 空闲 ≠ 干完。**全是拿 A 当 B**。）

## v1.2.0 ｜ 2026-10-19

**主题：音效支持批量添加，并给音效立了容量上限。**

boss原话：「音效支持批量添加，目前最大支持多大的文件，总文件多大？评估过了吗？」

### 查出来的三个事实（改之前）

| 问题 | 当时是什么样 |
|---|---|
| 批量添加 | **不支持**。选文件框没开多选，而且代码只取 `files[0]` —— 一次框选 10 个只进去第一个，**另外 9 个一声不响地没了**（静默丢文件） |
| 单文件上限 | 8MB（页面 + 主机两端都拦）。8MB ≈ 128k mp3 八分半 / 320k 三分半 / 未压缩 wav 57 秒 |
| 总容量 | **一条上限都没有**。没有条数上限、没有总字节上限，加到磁盘满为止。这项之前没评估过 |
| 顺带发现 | 主机端报错的那句人话传不到面板：`postJson` 在 `!ok` 时直接抛 `host responded 400`，把原因扔了 |

### boss的裁决（B 案）

- **单个 8MB + 总容量 200MB + 最多 30 条**（13:55 从 A/B/C/D 里选的 B）。
- 定位是「防误操作」的闸，不是容量规划：磁盘现在剩 600 多 GB，真正的风险是误选一个装满音乐的大文件夹，几百 MB 直接进 E 盘、以后备份同步一起放大。

### 改了什么

- **批量添加**：选文件框开多选；一次选中的整批逐个上传（一个文件一个请求，免得一次请求把 64MB 读体上限撞了）；结束后给一句汇总 —— 加了几个、没进去几个、原因分开列（格式不对 / 超 8MB / 条数满 / 总量满 / 主机端没收）。
- **两道新闸（主机端权威、写盘之前拦）**：条数 ≥30 拦、总量超 200MB 拦；报的是人话（「最多 30 条，现在已经有 30 条 —— 先删几条再加」「总容量上限 200MB，现在已用 197.0MB，这个文件放不下」）。
- **页面本地也预判一道**：条数/总量不够时不等文件传完就回话（大文件不白传）。
- **索引记 `bytes`**：老索引没记的去量一次文件，免得总量算成 0、闸门形同虚设。
- **覆盖同一条不撞墙**：同一个 id 重加时，旧的占用先减掉。
- **面板上多一行容量**：「容量：已用 xMB / 上限 200MB · n/30 条（单个最大 8MB，可一次多选）」，还剩多少一眼可见。
- **顺手补两个错**：
  ① `postJson` 现在把主机端那句人话带出来（不再只显示英文状态码）；
  ② 主机端单文件超限以前走 `decodeDataUrl` 返回 null，只报一句 `bad sound` —— 现在先按读体上限解出来再单独判 8MB，报的是「单个音效最多 8MB」；
  ③ `soundsCache` 是模块级变量，重新装配时不清理就会一直用上一轮读到的旧列表（面板显示假数据）—— 现在每次 `apply` 都从盘上重读。

### 验证

- **新增 `verify/sound_quota_check.cjs`（功能测试，不是读关键字）**：把主机端真的跑起来（假 webServer + 假 req/res），实测 13 项全过 —— 单个超限拦住且不落盘、第 31 条拦住、总量超拦住（报的已用数对得上 197.0MB）、覆盖同一条能过、删掉一条 usage 跟着降、回话带 usage。
- `verify/sound_check.cjs` 加了第 ⑩ 节 13 项（多选开关、整批交出、逐个上传、汇总文案、原因分列、人话透传、**页面与主机端三个数不漂**、两道闸在写盘前、`bytes` 记账、老索引量文件、usage 回话、容量行中英都有）。
- 全套脚本（full_verify / solid_fill_check / sound_check / sound_quota_check / icon_backdrop_probe / ink_cells_check / band_floor_check / four_features / gallery_locate / version_check）退出码全 0。
